# Scry 证据系统设计

## 证据对象

每项证据是独立持久化对象，不依赖前端消息解析结果。证据包含对话、组织、用户、Trace、消息、来源类型、来源工具、摘要、脱敏内容、内容哈希、置信度、关联度、状态、选择状态、备注和时间信息。

证据内容在写入前执行敏感字段和密钥模式脱敏，单项证据存储上限为 160 KB。相同对话、Trace、来源和内容哈希的证据只保存一次。

来自 MCP、日志、SSH 和附件的内容均按不可信数据处理。证据内容命中提示词注入规则时，系统自动将其标记为 `suspended`、取消选择并降低置信度，只有经过人工核验和恢复后才能参与回答。

## 评分模型

置信度由确定性因素计算，不接受模型自行填写：

```text
confidence = 0.34 * sourceReliability
           + 0.24 * dataQuality
           + 0.12 * freshness
           + 0.18 * executionIntegrity
           + 0.12 * directness
```

来源可靠性按直接主机巡检、可观测信号、告警、服务、仪表盘、MCP、文档和网页来源分级。数据质量根据空结果、结构完整性和截断状态计算；执行完整性区分成功与失败调用；直接性衡量证据是否直接描述目标系统状态。

关联度用于衡量证据与当前问题的关系：

```text
relevance = 0.62 * lexicalMatch + 0.38 * sourceCueMatch
```

词项匹配同时支持英文词项和中文双字词项；来源线索根据问题中的指标、日志、链路、服务、告警、主机、配置等运维语义计算。

## 状态机

- `active`：系统采集并可用于结论。
- `accepted`：用户明确采纳，仍可用于结论。
- `rejected`：用户驳回，自动取消选择，后续回答必须排除。
- `suspended`：证据等待人工核验，自动取消选择，后续回答暂不使用。

用户可以恢复证据、选择或取消选择、添加备注。每次处置进入证据操作历史和统一安全审计。

## 证据链

证据关系包括：

- `same_trace`：来自同一次对话、工具或 Loop 执行链。
- `corroborates`：不同来源包含高度相似的实体或状态，形成交叉印证。
- `related`：内容存在可解释的语义关联。
- `derived_from`：Loop 分析或验证结果由同一 Trace 中的原始证据派生。

聊天安全检查产生的 Trace 会继续传播到内置 MCP、查询工具、SSH 工具和 Loop 节点。证据关系、人工处置和修订回答均可按 Trace 和证据 ID 回溯。

## 证据约束重答

用户在 AI 页面选择证据后，可以添加补充要求并触发重新回答。重答过程不调用工具，只使用选定且未被驳回或挂起的证据；每个关键判断必须引用证据 ID。系统同时向模型提供明确排除的证据，避免旧结论继续引用已失效信息。

每次重答保存选定证据、排除证据、补充要求、助手消息和修订记录。选定证据增加 `used_for_revision` 操作事件，从而建立“原始问题 -> 工具证据 -> 人工处置 -> 修订结论”的完整链路。

## Agent 证据工具

- `list-evidence`：读取当前对话证据、状态、评分和备注。
- `get-evidence-chain`：读取证据节点及同链、印证、相关和派生关系。

Agent 被明确约束不得使用已驳回或挂起的证据形成事实结论。

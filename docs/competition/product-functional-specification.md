# Scry 软件产品功能说明书

文档版本：1.0.0  
产品名称：Scry  
适用赛题：第十五届中国软件杯 A2“面向麒麟操作系统的安全智能运维 Agent 设计与实现”  
适用平台：麒麟高级服务器操作系统 V11、LoongArch64  
编制日期：2026-07-19

## 1. 文档目的

本文说明 Scry 的产品定位、用户角色、运行环境、完整功能、主要操作流程、安全控制、比赛要求响应关系和验收方式。本文面向比赛评审、部署实施、系统管理员、运维工程师和安全审计人员，是软件功能演示、安装部署和功能测试的统一依据。

Scry 以自然语言作为运维入口，但不把大模型视为最终执行主体。模型负责理解需求、制定计划、选择受控工具和解释结果；身份、权限、参数、风险、审批与实际执行均由确定性的服务端组件控制。系统通过“实时感知、证据组织、推理决策、安全裁决、受控执行、结果验证、审计回放”形成完整闭环。

## 2. 产品定位

Scry 是部署在企业 Linux 与麒麟服务器环境中的安全智能运维平台，适用于教育、医疗、政企数据中心及其他需要国产化部署、最小权限控制和可追溯运维的场景。平台同时覆盖应用可观测、操作系统巡检、故障诊断、风险控制、自动化处置和知识复用。

产品解决以下问题：

1. 将复杂的日志、指标、链路和系统命令转化为自然语言可操作能力。
2. 通过统一证据对象减少模型基于不完整信息直接下结论的问题。
3. 通过 MCP 将查询、诊断和受控操作封装为具备 Schema 的标准工具。
4. 通过输入扫描、意图分类、命令复检、审批和受限账户约束高风险操作。
5. 通过 Loop 固化可重复的诊断与处置流程，减少人工步骤遗漏。
6. 通过证据链、运行记忆和审计记录支持复盘、复用和责任追踪。

## 3. 用户与权限

### 3.1 管理员

管理员负责组织设置、用户角色、模型端点、MCP 插件、SSH 主机、工具策略、Loop 定义、故障模拟和安全审计。管理员可以创建组织级记忆，管理受控命令，并审核高风险操作的授权边界。

### 3.2 运维编辑者

运维编辑者可以查询遥测数据、创建仪表盘和告警、使用 Agent、运行已授权 Loop、处置证据和维护个人记忆。其工具调用继续受角色权限、组织隔离、策略和审批约束。

### 3.3 只读查看者

只读查看者可以查看已授权的服务、指标、日志、链路、仪表盘、告警和 Agent 结果，但不能修改组织级配置、主机、策略或执行变更操作。

## 4. 系统组成

Scry 采用 B/S 架构，浏览器访问统一 Web Console。系统由以下服务组成：

| 组件 | 主要职责 |
|---|---|
| Web Console | 可观测页面、Agent 工作区、证据与记忆、Loop 编辑器、系统设置和审计界面 |
| Query Service | 身份与组织、统一查询、服务与基础设施分析、日志、链路、指标、仪表盘和告警 |
| Agent Service | 模型适配、Thread、MCP、证据、记忆、安全策略、SSH、Loop、调度和审计 |
| OpenTelemetry Collector | 接收和转发指标、日志与链路数据 |
| ClickHouse | 保存并分析大规模遥测数据 |
| PostgreSQL | 保存 Agent 运行记忆及持久化运行状态 |
| WASM SQLite | 保存 Agent 配置、对话、证据、Loop、插件、主机、策略和审计 |
| Alertmanager | 告警通知与状态管理 |
| scry-ops | 在受管主机上提供固定的只读和受控操作包装器 |

## 5. 统一可观测功能

### 5.1 应用性能监控

系统展示服务请求量、错误率、P50/P95/P99 延迟、Apdex、端点和外部依赖。用户可以从服务总览进入具体操作，按时间范围、服务、环境和属性筛选异常。

### 5.2 分布式链路

系统支持 Trace 查询、Span 过滤、瀑布图、火焰图、调用层级、错误节点和属性检查。Agent 可以通过有界查询获取异常链路，并将服务路径、错误签名与记忆拓扑关联，用于跨服务根因定位。

### 5.3 日志管理

系统支持日志全文检索、结构化字段过滤、时间范围、严重级别、服务和 Trace 关联。日志详情保留原始字段和资源属性，便于从告警或链路跳转到对应日志窗口。

### 5.4 指标查询

系统支持查询构建器、PromQL 和统一 Query Range 接口，可形成时间序列、表格、单值和分布类视图。Agent 的查询工具只允许有界、只读请求，并限制结果规模和超时时间。

### 5.5 基础设施与消息队列

系统展示主机 CPU、内存、磁盘、网络和进程类指标，并提供 Kafka 等消息队列的吞吐、积压、消费延迟与健康视图。基础设施与应用服务共享时间轴，可用于判断应用异常是否由操作系统资源造成。

### 5.6 仪表盘与告警

用户可以创建、复制、导入和编辑仪表盘，配置查询、公式、变量和多种图表。告警支持阈值、查询条件、评估窗口、通知渠道、历史状态和关联视图。Agent 可读取当前告警和已有仪表盘作为诊断入口。

## 6. OS 环境深度感知

Scry 通过两类路径感知操作系统：

1. OpenTelemetry 与基础设施指标持续提供 CPU、内存、磁盘、网络和进程状态。
2. 受管主机通过 `scry-ops` 固定包装器读取系统概况、磁盘使用率、内存使用、失败的 systemd 服务、监听端口和近期系统错误。

Agent 不接收任意 Shell 字符串。只读巡检只能选择固定命令 ID；受控变更只能选择管理员预先保存并启用的操作 ID。主机连接配置包含主机名、端口、用户、主机密钥指纹、认证类型和启用状态，秘密字段加密保存，列表接口不返回密码或私钥。

典型操作流程：用户询问“为什么磁盘告警持续触发”，Agent 先读取告警与基础设施指标，再调用磁盘使用包装器和近期错误工具，将结果写入证据对象，最后输出结论、证据和下一步，而不是直接执行清理。

## 7. 智能运维 Agent

### 7.1 工作区

Agent 工作区由任务线程、对话区和检查器组成。用户可以创建、搜索、切换和删除 Thread；消息与工具状态持久化，刷新页面后可恢复。输入支持多行文本、常见文本附件、停止执行和重新生成。

### 7.2 工作模式

- 诊断模式：以只读查询和根因分析为主，不主动执行变更。
- 规划模式：输出可审查的步骤、依赖、风险和验证条件。
- 操作模式：允许在策略与审批通过后调用受控操作，并必须执行结果验证。

复杂任务先发布 2 至 6 步计划。模型必须先使用工具获得事实，再形成结论；输出采用“结论、证据、下一步”结构，并区分已验证事实、推断和建议。

### 7.3 模型配置

系统支持 OpenAI Responses、Anthropic Messages 及兼容端点。管理员可配置模型、Base URL、API Key、温度、输出长度、最大步骤、超时、重试和工具选择。API Key 使用主密钥加密保存，页面只显示是否已配置。

### 7.4 结构化结果

工具可以返回 A2UI 表格、指标摘要、计划、风险状态和步骤进度。前端验证结构版本并限制行列数量，未知结构回退到 JSON 检查器。模型正文不重复完整原始结果，从而保持页面可读性和上下文效率。

## 8. MCP 运维插件化

Scry 内置 MCP Streamable HTTP Server，提供：

- 诊断计划发布。
- 服务、告警和仪表盘读取。
- 指标、日志和链路 Query Range。
- 安全意图评估。
- SSH 主机目录、只读巡检和受控操作。
- 证据列表与证据链查询。
- TopoMem 记忆搜索、写入、检查、维护和遗忘。

内置 `tools/list` 运行时目录包含 16 个工具，名称采用 camelCase；装载到 Agent 后统一增加 `scry_` 命名空间，例如 `querySignals` 对应 `scry_querySignals`，`sshReadonlyInspect` 对应 `scry_sshReadonlyInspect`。全部工具的输入 Schema 使用 `additionalProperties=false` 拒绝额外字段，并提供中文字段说明、枚举范围、默认值、取值来源和完整调用示例。调用参数就是与 `inputSchema` 匹配的单个 JSON 对象，不允许再添加 `args`、`arguments`、`input`、`payload`、`request`、`body` 或 `query` 包装层；无参数工具固定传 `{}`。系统不向模型供应商发送兼容性不稳定的 provider strict 元数据，确定性校验仍在 MCP Server 工具边界执行。

`querySignals` 不要求模型构造 Query Range V3 底层协议，而是使用统一的扁平高层格式：顶层必须声明 `signal=logs|traces|metrics`，并可使用 `lookbackMinutes`、`caseId`、`serviceNames`、`filters`、`resultMode`、`groupBy` 和 `stepSeconds`。日志查询提供 `searchText` 与 `severities`，链路查询提供 `operation`、`errorOnly` 与 `minDurationMs`，指标查询要求 `metricName` 并支持聚合和指标类型。工具内部负责生成 `queryType=builder`、`builderQueries.A`、时间窗口、面板类型、字段作用域和聚合参数，模型不能传入 `query`、`compositeQuery`、`logQueries`、`builderQueries`、`start` 或 `end` 等底层字段。

参数在工具入口进行 Schema 校验。日志与链路聚合只接受 `count` 或 `rate`，指标查询必须提供指标名，`in`/`nin` 操作必须使用数组，时间范围、结果数量和时间桶均有上限。计划、安全、证据、记忆和 SSH 工具同样采用自描述契约：证据、记忆、主机和命令 ID 必须来自前置工具真实输出，`remember` 的正文固定为字符串，受控 SSH 工具不接受主机名、IP 或 Shell 文本。校验失败时 Agent 只修正错误字段，不切换到底层协议试错；工具错误、无数据和观测到服务故障作为三种不同状态处理。

内置 MCP Server 在初始化阶段发布统一调用协议，Agent 使用同一份受版本控制的协议常量直接构建系统上下文。MCP Client 不再自动转发 Server Instructions，避免自定义 Responses 兼容端点因重复 Guidance 或扩展元数据进入空推理循环；外部插件指令也不会扩大为系统权限。外部工具仍以其 `tools/list` Schema 作为唯一参数依据。

管理员还可以注册远程 MCP 服务，配置名称、地址、启用状态、超时和独立认证头。认证头加密保存，外部插件不会获得用户的 Scry JWT。单个远程插件连接失败时被隔离，不影响其他工具；内置安全工具不可用时 Agent 不会静默降级执行。

## 9. 安全护栏

### 9.1 Prompt Injection 防护

用户输入、附件、MCP 输出和 SSH 输出均视为不可信数据。系统在模型调用前进行 Unicode 归一化、零宽字符清理，并检测指令覆盖、系统提示泄露、安全绕过、角色混淆和编码载荷。命中高风险规则的请求被拒绝或挂起，并生成 traceId。

### 9.2 意图风险分类

系统将请求划分为只读查询、低风险变更、高风险操作、权限提升、敏感信息访问和不可判定等类别，输出 `allow`、`require-approval` 或 `deny`。该结果由服务端策略决定，模型不能修改。

### 9.3 命令二次过滤

在 SSH 或操作工具执行前，系统再次检查命令和参数，识别 `rm`、不安全 `chmod`、提权、管道、重定向、命令替换、设备写入、关键路径修改和敏感文件读取。审批绑定工具、目标和参数哈希，审批后参数变化将使原审批失效。

### 9.4 最小权限执行

受管主机使用独立 `scry-ops` 账户、公钥认证、ForceCommand、无 TTY、无端口转发和无隧道。包装器由 root 持有且不可被运行账户修改；sudoers 仅授权精确包装器路径和允许的服务。Agent Service 自身以非 root 用户运行，不挂载 Docker Socket，不授予额外 Linux capabilities。

### 9.5 审计闭环

统一审计以 traceId 串联请求接收、注入扫描、意图分类、策略裁决、审批、命令复检、工具开始、完成、失败和结果验证。审计保存结构化摘要、风险分、输入哈希、用户、组织、目标和时间，不保存模型 Key、SSH 私钥或完整敏感输出。

## 10. 证据机制

每项工具结果可以形成独立证据对象，包含来源、标题、摘要、脱敏内容、哈希、置信度、关联度、状态、选择状态、备注、关系和操作历史。

置信度由来源可靠性、数据质量、新鲜度、执行完整性和直接性确定；关联度由问题词项匹配和来源线索匹配确定。用户可以接受、驳回、挂起、恢复、选择、取消选择和备注证据。

证据关系包括同一执行链、交叉印证、相关和派生。用户选定证据后可以要求 Agent 重新回答；重答只能使用选定且未被驳回或挂起的证据，并保存选定项、排除项、补充要求和修订记录。

## 11. 运行记忆

记忆分为工作、情景、语义和程序记忆，作用域包括组织、用户、Agent、Thread 和 Loop。每项记忆包含正文、摘要、服务、标签、关键词、置信度、重要性、活性、来源、关系、维护记录和可预览分块。

TopoMem 优先根据当前 Trace 的异常服务路径检索，再使用错误签名和分块相似度重排；缺少可靠拓扑时回退到本地词法与稠密检索。记忆只用于形成待验证假设，不替代当前证据。

维护任务执行活性衰减、访问强化、重复合并、冲突检测、到期归档和低活性归档。遗忘操作清除正文与可检索字段，仅保留审计骨架。

## 12. Loop 自动化

Loop 是可版本化、可调度、可暂停恢复的运维流程。支持以下节点：

- Agent 推理。
- 服务、告警、仪表盘读取。
- MCP 工具调用。
- 安全检查。
- 人工审批。
- 受控操作与结果验证。
- 条件分支、并行分支和循环。

Loop 支持手动运行、Cron、时区和事件触发，保存输入 Schema、标签、版本历史、步骤状态和运行记录。系统提供安全决策、磁盘爆满、僵尸进程、磁盘 I/O、配置漂移、服务恢复、网络暴露面、综合根因分析、Prompt Injection 审查和记忆维护等预设。

即使自定义 Loop 未显式放置安全节点，聊天入口和 SSH/MCP 操作仍经过不可绕过的底层安全策略。

## 13. 故障模拟

管理员可在设置中启用模拟环境，配置轻量、标准或高负载档位、生成间隔、回填时间和信号类型。系统支持：

| 编号 | 场景 | 主要诊断信号 |
|---|---|---|
| `case-000` | 健康基线 | 正常吞吐、延迟、错误率和主机资源 |
| `case-001` | PostgreSQL 连接池耗尽 | used/idle/max、连接获取超时、数据库连接上限日志 |
| `case-002` | PostgreSQL 表膨胀与自动清理滞后 | dead rows、表体积、autovacuum age、查询超时 |
| `case-003` | Valkey/Redis 客户端连接上限 | connected clients、maxclients、rejected connections |
| `case-004` | Redis 持久化 fork 延迟 | RDB 保存、fork 时长、命令延迟、主机内存 |
| `case-005` | Kafka 消费积压与频繁再均衡 | Consumer Lag、生产/消费速率、rebalance、消费 Span |
| `case-006` | 外部服务 TLS 证书过期 | 证书剩余有效期、TLS 握手错误、TCP 对照探测 |
| `case-007` | DNS 解析失败 | lookup 时长、SERVFAIL、上游 DNS 超时、IP 直连对照 |
| `case-008` | gRPC 截止时间不匹配 | 客户端 deadline、服务端耗时、DeadlineExceeded |
| `case-009` | 外部 API 速率限制 | HTTP 429、Retry-After、剩余配额和请求速率 |
| `case-010` | 响应结构不兼容 | 下游 HTTP 200、Schema 版本、字段类型解析错误 |
| `case-011` | 内存泄漏与 OOM 重启 | RSS、内存限制、GC 回收率、OOMKilled、重启次数 |
| `case-012` | CPU 与线程池饱和 | CPU、活动线程、线程上限、队列深度和拒绝执行 |
| `case-013` | 日志增长导致磁盘耗尽 | 文件系统利用率、剩余空间、ENOSPC、轮转失败 |
| `case-014` | 磁盘 I/O 延迟抖动 | 设备利用率、写延迟、CPU iowait、数据库等待事件 |
| `case-015` | 配置漂移导致鉴权失败 | 实例级配置摘要、JWT 验签错误和健康实例对照 |
| `case-016` | 服务崩溃与不可用 | connection refused、健康状态、CrashLoopBackOff |
| `case-017` | 未授权网络监听暴露 | 监听端口、批准基线、进程归属和外部连接 |
| `case-018` | 僵尸进程持续堆积 | zombie、父进程、进程上限、fork EAGAIN |
| `case-019` | 内存泄漏与消息积压复合故障 | OOM 重启、消费者再均衡、Lag 与 Broker 健康对照 |

每个场景在统一定义中保存用户症状、调用拓扑、故障比例、根因节点、异常签名、根服务与上游日志、干扰日志、业务指标、主机指标、消息指标、标准诊断、处置步骤、验证点和高风险误操作。生成器按定义同时产生故障调用、正常依赖对照、根因异常、上游错误传播和趋势数据；服务日志通过 Trace ID 与对应 Span ID 关联，场景指标同时包含故障前基线点和当前故障点。

模拟遥测只携带 `scry.debug=true`、`scry.dataset=diagnostic-evaluation` 和不透明的 `scry.debug.case_id=case-xxx`，不写入场景名称、根因服务或根因标签，避免 Agent 通过元数据直接获得答案。场景目录接口仅提供名称、类别、难度、用户症状、拓扑和可用信号；管理员真值接口独立提供预期根因、关键证据、处置和验证标准，用于测试评分与复盘。

系统提供端到端 Agent 准确性评测工具。工具自动选择场景、生成高密度 OTLP 数据、等待 Collector 入库、创建隔离对话、要求 Agent 使用工具检索证据，并按根因服务、根因机制、证据质量、处置方案、恢复验证和安全性六个维度评分。评测输出逐案例结果、证据数量、危险建议和总体平均分；默认覆盖数据库、消息队列、DNS、接口契约、内存、磁盘和复合故障，也可一次运行全部故障场景。

清理流程根据调试资源标识删除 Trace、Log、Metric、服务拓扑、异常索引和自动告警规则，不影响真实遥测。该模块用于验证 Agent 对应用故障、OS 故障、依赖故障和复合故障的感知、证据构建、安全决策及 Loop 处置能力。

## 15. 非功能性要求

### 15.1 安全性

系统默认拒绝高风险或不可判定操作；秘密加密保存；所有领域查询继承当前用户身份；组织级对象执行组织隔离；高风险工具需要审批；主机操作遵循最小权限。

### 15.2 可靠性

工具调用设置连接、响应和总体超时；远程插件故障隔离；对话与 Loop 状态持久化；未知 A2UI 数据可降级显示；记忆与证据均有大小、数量和状态边界。

### 15.3 可扩展性

MCP 插件、Loop DSL、A2UI Schema、模型供应商适配和工具策略均具有明确扩展点。新增能力不需要把任意命令权限交给模型。

### 15.4 可维护性

服务边界、数据库职责、接口契约和部署脚本独立。系统提供健康检查、systemd 服务、日志、审计、版本化 Loop 和可重复验收脚本。

### 15.5 性能

遥测查询由 ClickHouse 承担；Agent 本地安全裁决不依赖外部模型；工具查询有界并限制结果大小；前端按路由拆分。性能验收记录健康接口、MCP 工具目录、Agent 首个流事件和安全裁决的 P50/P95/P99。

## 16. 麒麟部署

目标环境为麒麟高级服务器操作系统 V11、LoongArch64。Query Service 必须在目标机使用 LoongArch Go 和 CGO 原生编译；Agent 使用 Node.js 22.13 及以上版本，数据库驱动采用 WASM SQLite，避免依赖特定 CPU 的原生扩展；Frontend 构建为 Nginx 静态资源。

部署流程包括平台预检、Node.js 准备、PostgreSQL 初始化、Query/Agent/Frontend 构建、systemd 安装、Nginx 配置和验收。压缩包不包含 `node_modules`、Go 模块缓存、测试目录或本地构建缓存，依赖根据锁文件在目标机安装。

## 17. 产品边界

1. Scry 不允许模型直接连接数据库执行任意 SQL。
2. 运行记忆是历史经验，不代表当前系统事实，结论必须由当前证据验证。
3. Prompt Injection 检测降低风险，但不能替代主机权限隔离和审批。
4. 外部模型、ClickHouse 和 PostgreSQL 的可用性由部署环境保障，Scry 提供连接测试和故障提示。
5. 模拟数据仅用于演示和测试，正式环境应关闭模拟开关。

## 18. 建议演示流程

1. 启用“磁盘空间耗尽”模拟场景。
2. 在 Agent 中询问“为什么磁盘告警持续触发，帮我处理”。
3. 展示 Agent 发布计划、读取告警、指标和主机磁盘状态。
4. 在证据栏展示置信度、关联度和证据关系。
5. 选择安全决策 Loop，展示危险清理动作进入审批。
6. 拒绝一次审批，确认系统不执行；再次使用允许的包装器完成受控操作。
7. 展示验证节点、最终结论和 traceId 审计回放。
8. 展示相关运行记忆与当前证据的区分。
9. 在麒麟目标机执行验收脚本并展示架构、非 root 服务用户和健康接口。

以上流程覆盖功能完整性、创新实用性、文档演示和麒麟平台运行要求。

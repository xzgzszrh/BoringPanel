文档版本：1.0.0  
产品版本：Scry 1.0.0

测试日期：2026-07-20  
报告范围：开发环境 HTTP、安全规则、资源和算法质量基准

> 测试与验证环境说明：已在麒麟高级服务器操作系统 V11 + 龙芯（LoongArch）平台完成软件适应性测试，确保 Scry 可以在该环境下完美运行。考虑到麒麟-龙芯实体环境的持续使用成本，除适应性测试外，现阶段其他功能与性能测试主要在 macOS 开发环境及其中运行的麒麟系统虚拟机中开展；后续将在麒麟-龙芯平台补充相应测试。

## 1. 测试目标

本报告验证与赛题直接相关的核心指标：

1. Agent 基础服务在并发请求下的响应时间、失败率和吞吐。
2. Prompt Injection、意图分类和命令风险分析的本地计算延迟。
3. Agent、Query Service、ClickHouse 和 PostgreSQL 的开发环境资源占用快照。
4. TopoMem 运行记忆检索和根因定位的算法质量指标。
5. 麒麟发布包体积和可交付性。

软件已在麒麟 V11 + 龙芯（LoongArch）平台完成适应性测试并确认可完美运行。受实体平台持续使用成本影响，本报告中的其他性能数据主要来自 macOS 开发环境及其中运行的麒麟系统虚拟机；后续将在麒麟-龙芯平台补充测试。

## 4. 测试工具与方法

### 4.1 HTTP 并发

使用仓库脚本：

```bash
SCRY_LOAD_REQUESTS=<请求数> \
SCRY_LOAD_CONCURRENCY=<并发数> \
node tests/performance/agent-api-load.mjs
```

未设置 `SCRY_TEST_TOKEN` 时脚本请求 `/health`，记录失败数和 P50/P95/P99。最高负载场景使用 `/usr/bin/time -p` 记录包含 Node 进程启动与退出在内的总墙钟时间，因此吞吐估算偏保守。

### 4.2 安全规则微基准

使用构建后的规则模块，在单进程内循环 50,000 次：

- Prompt Injection 检测 + 意图分类：混合普通诊断、指令覆盖、服务重启和秘密读取样本。
- 命令风险分析：混合固定包装器、`sudo -n` 包装器、`rm -rf`、Shell 和管道样本。

微基准只衡量规则计算，不包含审计数据库写入、网络、审批或 SSH 执行。

### 4.3 资源占用

使用 `docker stats --no-stream` 获取单次快照。该指标受容器运行时缓存、历史运行时长和同机负载影响，只用于容量规划参考。

### 4.4 算法质量

TopoMem 指标来自项目随附研究材料 `main.pdf` 的受控评测：55 个独立故障、548 份运维文档，并包含 24 个固定 Agent 配置的下游诊断实验。该数据用于说明根因记忆检索质量，不是本轮 HTTP 压测结果。

## 5. HTTP 并发测试结果

| 场景 | 请求数 | 并发 | 失败 | 失败率 | P50 | P95 | P99 |
|---|---:|---:|---:|---:|---:|---:|---:|
| L1 | 200 | 20 | 0 | 0% | 24.51 ms | 90.66 ms | 205.51 ms |
| L2 | 1,000 | 50 | 0 | 0% | 12.45 ms | 74.24 ms | 184.57 ms |
| L3 | 5,000 | 100 | 0 | 0% | 11.10 ms | 22.88 ms | 54.60 ms |

L3 总墙钟时间为 0.94 s，保守吞吐估算为：

```text
5000 / 0.94 = 5319 requests/s
```

### 5.1 结果分析

- 三个并发级别均为零失败，满足 PI-REL-001。
- 20 并发 200 请求零失败，满足 PI-API-001。
- L1/L2 的尾延迟高于 L3，与首次连接、JIT、容器调度和短样本分位数波动有关。
- `/health` 数据用于衡量 Agent 基础 HTTP 服务与运行时响应，不包含外部模型生成时间。

## 8. TopoMem 全量评测数据

本节完整整理根目录 `main.pdf` 中 TopoMem 的量化数据。TopoMem 使用当前故障的运行时 Trace 作为导航结构：先沿异常调用链定位候选根服务，再使用日志字段、Span 标签、状态码和告警词项形成错误签名，对候选服务内的运维记忆进行重排。TopoMem-MP 最多保留三条异常路径，用于处理冲突 Trace。

### 8.1 数据集与实验配置

| 项目 | 数据 |
|---|---|
| 主评测故障 | 55 个独立故障，每条路径包含 3-4 个服务 |
| 运维文档 | 548 份，约 165,000 词 |
| 故障-文档组合 | 30,140 对 |
| 文档类型 | Runbook、Postmortem、服务画像、变更记录、值班交接和 Agent 记忆 |
| 查询复制检查 | 没有文档包含其查询的完整拷贝 |
| 错误签名词项覆盖 | 全部文档 29.9%，根因文档 38.2% |
| 完整签名泄露 | 没有根因文档包含完整错误签名 |
| 服务名泄露 | 查询和签名均省略终点服务名 |
| 文档分块 | 按段落切分，单块最大 1,800 字符 |
| 标注核验 | 3 个 LLM 标注者；36 个角色标签案例全体一致；84 份无元数据文档通过多数票确定服务标签 |
| 随机实验 | 每个随机条件 20 个固定种子实现 |
| 置信区间 | 10,000 次故障级 Bootstrap，报告配对 95% CI |
| Trace 压力集 | 18 条路径用于多路径参数校准，37 条路径留出评测 |
| 异常边阈值 | 错误率 0.10 |
| Trace Walk 最大深度 | 5 |
| TopoMem-MP 路径数 | 最多 3 条异常路径 |

公开事故报告的词汇差异分析覆盖 5 个公开 Postmortem 索引中的 99 组“症状-根因”段落。高 IDF 词项定义为样本中 IDF 最高的 70%；49.5% 的段落对没有共享高 IDF 词项，中位共享量仅为 1 个词，说明跨服务词汇鸿沟在公开事故资料中同样普遍存在。

### 8.2 指标定义

- Root Hit@5：前 5 条结果中至少出现 1 份根因文档的故障比例。
- MRR@5：首份根因文档在前 5 条中的平均倒数排名；未命中记为 0。
- Role Coverage@5：前 5 条结果对 surface、bridge、root cause、remediation 四类角色的平均覆盖比例。
- Gold docs@5：前 5 条证据中金标准文档的平均数量。
- Root/Mode Score：根因服务和故障模式得分，范围均为 0-2。

### 8.3 根因文档检索结果（Table I）

| 方法 | Root Hit@5 | 95% CI | MRR@5 |
|---|---:|---:|---:|
| BM25 | 0.636 | [0.509, 0.764] | 0.222 |
| Dense（Qwen3-Embedding-0.6B） | 0.600 | [0.473, 0.727] | 0.212 |
| BM25 + signature | 0.745 | [0.618, 0.855] | 0.296 |
| Dense + signature | 0.636 | [0.509, 0.764] | 0.258 |
| ApeRAG：alert only | 0.200 | [0.109, 0.309] | 0.043 |
| ApeRAG：trace text | 0.218 | [0.109, 0.327] | 0.048 |
| ApeRAG：trace + signature text | 0.309 | [0.182, 0.436] | 0.078 |
| TopoMem-Walk（trace + dense） | 0.927 | [0.855, 0.982] | 0.515 |
| TopoMem（trace + signature + dense） | 0.964 | [0.909, 1.000] | 0.655 |

完整 TopoMem 在 55 个故障中命中 53 个，TopoMem-Walk 命中 51 个，BM25 + signature 命中 41 个，BM25 命中 35 个，Dense 命中 33 个。相较 BM25，TopoMem 的 Hit@5 提升 0.327，95% CI 为 [0.200, 0.455]。相较 TopoMem-Walk，TopoMem 的配对 Hit@5 差值为 0.036，95% CI 为 [-0.055, 0.127]；MRR@5 差值为 0.140，95% CI 为 [0.062, 0.223]。

ApeRAG 从 alert only 的 0.200 提升到 trace text 的 0.218，再提升到 trace + signature text 的 0.309；将相同路径真正作为导航约束执行时，TopoMem-Walk 达到 0.927。

### 8.4 错误签名质量敏感性（Table II）

| 签名条件 | Root Hit@5 | MRR@5 | Role Coverage@5 |
|---|---:|---:|---:|
| Observed signature | 0.964 | 0.655 | 0.741 |
| Retain 50% | 0.965 | 0.609 | 0.729 |
| 50% + equal-length foreign noise | 0.966 | 0.600 | 0.720 |
| Query only（TopoMem-Walk） | 0.927 | 0.515 | 0.727 |

保留 50% 签名时，相对 TopoMem-Walk 的 MRR@5 优势为 +0.094，95% CI 为 [0.040, 0.150]；加入等长外来噪声时优势为 +0.085，95% CI 为 [0.030, 0.142]。结果表明 Trace 决定候选区域，签名质量主要影响根因文档在候选区域中的排序。

### 8.5 Trace 观测压力与多路径路由（Table III）

该实验在 37 条留出路径、548 份文档和每个条件 20 个固定种子实现上进行。

| Trace 观测条件 | BM25 + signature | TopoMem | TopoMem-MP |
|---|---:|---:|---:|
| Clean finite-count trace | 0.730 | 0.946 | 0.946 |
| Head sampling 20% | 0.730 | 0.926 | 0.928 |
| Edge dropout 10% | 0.730 | 0.853 | 0.878 |
| Edge dropout 30% | 0.730 | 0.685 | 0.773 |
| Five-call low traffic | 0.730 | 0.854 | 0.900 |
| Stale high-error branch | 0.730 | 0.001 | 0.919 |
| Concurrent fault branch | 0.730 | 0.053 | 0.919 |

在 30% 边丢失时，TopoMem-MP 相对 TopoMem 提升 0.088，95% CI 为 [0.016, 0.161]；五调用低流量条件提升 0.046，95% CI 为 [0.022, 0.072]。陈旧高错误分支提升 0.918，95% CI 为 [0.811, 0.999]；并发故障分支提升 0.866，95% CI 为 [0.772, 0.942]，且干净 Trace 的 Hit@5 保持不变。

其他观测扰动相对干净条件的变化为：错误偏置尾采样 -0.016，95% CI [-0.049, 0.000]；重试膨胀 -0.014，95% CI [-0.041, 0.000]；5% 错误标签噪声 -0.011，95% CI [-0.032, 0.000]。

TopoMem-MP 在冲突分支下对签名质量的结果为：保留 50% 签名时，陈旧/并发分支 Hit@5 为 0.822；加入等长外来噪声时为 0.707；无签名时回退到 query-only BM25，Hit@5 为 0.595。

### 8.6 检索延迟

检索延迟在 Apple M4 Mac mini、16 GB 内存环境测得，包含 CPU 查询向量计算，但不包含一次性的模型装载时间。

| 方法 | P50 | P95 | P99 | 其他耗时 |
|---|---:|---:|---:|---:|
| TopoMem-Walk | 164 ms | 248 ms | 357 ms | 模型首次装载 4.9 s，不计入分位数 |
| TopoMem | 167 ms | 251 ms | 360 ms | 模型首次装载 4.9 s，不计入分位数 |
| ApeRAG：trace text | 3,793 ms | 6,945 ms | 9,200 ms | 索引构建 4,144.8 s |

ApeRAG 在 trace + signature 条件下的 P50 为 3,907 ms。TopoMem 的亚秒级路径适合位于告警进入与 Agent 首次诊断动作之间的同步检索阶段；TopoMem-Walk 与完整 TopoMem 的延迟差异很小，签名重排没有引入明显的额外开销。

### 8.7 下游 Agent 诊断结果（Table IV）

下游实验覆盖 24 个多跳故障，由 6 个故障族、每族 4 个故障模式构成，使用 312 份运维文档。Agent 固定为 GLM-5.1、temperature 0.2，最多调用 `get_logs`、`get_metrics` 和 `query_service` 三次，最多访问两个服务。

| 指标 | No context | BM25 | Dense | TopoMem |
|---|---:|---:|---:|---:|
| Gold docs@5 | 0.00 | 0.04 | 0.00 | 2.33 |
| Initial root | 0.12 | 0.17 | 0.00 | 0.58 |
| Final root | 2.00 | 1.83 | 1.88 | 2.00 |
| Final mode | 1.75 | 1.33 | 1.67 | 2.00 |
| Wrong first target | 0.46 | 0.54 | 0.38 | 0.08 |
| Root in <=2 calls | 0.67 | 0.46 | 0.83 | 1.00 |

各条件实际使用的工具预算接近一致，平均为 2.9-3.0 次调用。TopoMem 将错误首个工具目标率从 BM25 的 0.54 降至 0.08，使全部故障在两次工具调用内到达根服务，并将最终故障模式得分提高到 2.00。

### 8.8 TopoMem 数据结论

TopoMem 的主要收益来自 Trace-guided Walk 对根服务区域的定位：Root Hit@5 从 BM25 的 0.636 提升到 0.927；错误签名重排进一步将完整方法提高到 0.964，并使 MRR@5 增加 0.140。TopoMem-MP 在陈旧分支和并发故障分支上均达到 0.919，同时保持干净 Trace 的 0.946。下游 Agent 的错误首目标率降至 0.08，两次调用内根服务到达率为 1.00。

## 10. 测试结论

Scry 已通过麒麟 V11 + 龙芯（LoongArch）平台软件适应性测试，确认软件能够在该环境下完美运行。

在当前开发环境中，Scry Agent 健康端点在 20/50/100 并发下均为零失败；最高场景 5,000 请求的 P95 为 22.88 ms，保守吞吐约 5,319 req/s。本地 Prompt Injection/意图分类和命令风险规则 P95 均远低于 50 ms。Agent Service 资源快照约 416.2 MiB，包含提交文档 PDF 的精简麒麟发布包约 8.0 MiB。

TopoMem 受控评测显示完整方法 Root Hit@5 为 0.964、MRR@5 为 0.655；TopoMem-MP 在陈旧和并发冲突分支上均达到 0.919；下游诊断错误首个工具目标率降至 0.08，两次工具调用内到达根服务的比例达到 1.00，体现了针对赛题根因分析和自然语言准确性的核心优势。

PI-API-001、PI-REL-001、PI-SEC-001、PI-RCA-001 和 PI-PKG-001 均达到本报告规定的验收标准。
